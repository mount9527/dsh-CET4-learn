# 数据包组织规范（dsh-CET4-learn）

> 这份文档只描述**目录与文件约定**，不包含任何题目、录音或词表内容。
> 真实的题库请放在**私有仓库**或本机资料目录里；公开仓库只放代码与本文档。

> **先分清两种数据**：随包分发的 `starter/` 是**原创示例题库**（不碰真题，可公开分发，见 `NOTICE.md` 第 3 节），
> 它不是本文说的「数据包」；本文讲的是使用者自备真题的目录约定。两者结构相同，所以同一套构建产物格式通吃。

## 1. 为什么数据不进公开仓库

CET-4 的试题、听力录音、答案与词汇释义的著作权归原权利人（考试主办机构、出版方）。
把真题 PDF、听力音频或成规模的答案/释义放进公开仓库，等于向公众提供复制件，
不属于「个人学习研究」的合理使用。因此：

- **公开仓库（本仓库）**：只放代码、文档、目录模板。
- **数据包**：放在私有仓库或本机目录，例如 `~/.dsh/dsh-cet4/data-pack/`；
  构建时用 `--src` 指过去，产物默认写到 `~/.dsh/dsh-cet4/data/`。
- 如果确实想把数据也放到 GitHub：请把仓库设为 **Private**，或另开一个私有数据仓，
  不要把数据推到公开仓库。

## 2. 数据包根目录（按题型分类）

构建脚本按**目录名前两位**识别，后面的名字随意：

```
data-pack/
├─ 01 真题试卷/
│  └─ <考期>/<套>/<任意文件名>.pdf          # 也可以是同名 .txt 纯文本卷
├─ 02 答案/
│  └─ <任意名>.csv                          # 答案总表：场次,套数,题号,题型,答案,选词原词
├─ 03 听力原文/
│  └─ <YYYY年M月第N套>_听力原文.txt          # 可选；缺了听力题只能靠听
├─ 04 词汇/
│  ├─ 四级核心词汇1500.csv
│  └─ 四级大纲词汇4500.csv
├─ 05 听力音频/
│  └─ <YYYY年M月第N套>听力音频.aac           # 可选；支持 .aac/.m4a/.mp3
└─ audio-tracks.json                        # 可选：分段表（见第 5 节）
```

为什么按题型而不是按考期：一份答案 CSV 与一份词表要覆盖所有考期；
按题型放，新增考期只是往 `01` 里多一个文件夹，不用动其它目录。

## 3. 以后怎么加新内容

### 加一套新真题

1. 把 PDF 放进 `01 真题试卷/<考期>/<套>/`；
2. 在 `02 答案/<总表>.csv` 里补这套的 55 个客观题答案（听力 1–25、选词 26–35、匹配 36–45、阅读 46–55）；
3. 有听力原文就放 `03 听力原文/`，有录音就放 `05 听力音频/`（文件名带上考期与套号）；
4. `npm run build:data -- --src <数据包路径>`，再 `npm run check:data` 确认 `problems` 为空。

### 加一份新录音

放进 `05 听力音频/`，文件名必须能解析出「YYYY年M月…第N套」。构建会：

- 用同名听力原文与各套选项做关键词比对，判断它属于哪一套；
- 没有原文时按文件名归属并标 `audioVerified: false`（界面会提示「录音按套号推定」）。

### 加一批新单词

当前构建只识别两个词表文件（文件名分别含 `1500`、`4500` 或 `3600`）。
想加**新的词表分册**（例如「考研核心词」「物流专业词」），需要先扩展构建脚本与界面，
约定如下（供后续实现）：

- 文件：`04 词汇/<名称>.csv`，列与现有词表一致（编号、单词、音标、考频、释义、词性、例句、例句中译）；
- 产物：`vocab-<slug>.json` + `index.json` 里多一个 deck；
- 界面：首页按 deck 动态生成卡片，进度仍按单词共享（同一个词在多个分册里只算一次）。

在扩展完成前，新增 CSV 会被构建忽略，不会报错。

### 加分段表（按篇跳转）

`audio-tracks.json` 只是「某份录音第 N 篇从第几秒到第几秒」，可以放在：
`--tracks` 参数、`CET4_TRACKS` 环境变量、数据包根目录、`05 听力音频/` 或 `~/.dsh/dsh-cet4/`。
构建会用音频真实时长校验，任何一段越界就整份作废并写 warning。

## 4. 数据包清单（建议）

在数据包根目录放一份 `pack.json`，方便自己记录版本与来源（构建不依赖它）：

```json
{
  "name": "cet4-2023-2026",
  "updatedAt": "2026-11-07",
  "source": "自购真题册 / 听力音频",
  "periods": ["2023-06", "2023-12", "2024-06", "2024-12", "2025-06", "2025-12", "2026-06"],
  "note": "仅个人学习使用，不公开分发"
}
```

## 5. 私有仓库的推荐做法

```bash
# 数据包单独一个私有仓库（GitHub → New repository → Private）
git init
git add .
git commit -m "data: CET-4 2023-2026 pack"
git remote add origin git@github.com:mount9527/dsh-cet4-data.git
git push -u origin main
```

在每台机器上：

```bash
git clone <私有数据仓> ~/.dsh/dsh-cet4/data-pack
npm run build:data -- --src ~/.dsh/dsh-cet4/data-pack
```

升级插件（`npm update dsh-cet4`）不会影响 `~/.dsh/dsh-cet4/`，题库与音频都还在。

## 6. 校验

```bash
npm run check:data      # 真题题库
npm run check:starter   # 内置示例题库（无音频、kind=starter、词数自洽）
```

`check:data` 会检查：答案数量、选词字母是否在词库、长篇阅读答案是否指向存在的段落、选项数、
选项是否粘连了下一段说明、听力题数/音轨是否存在、`index.json` 的录音统计是否与卷宗一致。

`check:starter` 是发版护栏，拦这四类事故：音频混进 `starter/`、`index.json` 忘了标 `kind: "starter"`、
卷宗里写了 `listening.audio`、`index.json` 声明的词数与词表实际条数不一致。

## 7. 示例卷的字段约定（想自己加原创卷时）

`starter/papers/*.json` 与真题卷结构相同，只有一处差别：**听力不指向音频文件**。

```json
{
  "synth": true,
  "listening": {
    "synth": true,
    "track": "",
    "audio": "",
    "verified": true,
    "passages": [{ "key": "A1", "section": "A", "from": 1, "to": 2, "text": "…", "questions": [] }]
  }
}
```

- `listening.synth: true` 时前端不渲染 `<audio>`，改用 `SpeechSynthesis` 逐句朗读 `passages[].text`，
  按篇点击单读、读完即停；交卷前不显示原文按钮（原文就是朗读内容，先给等于给答案）。
- 没有 `start` / `end` 时间轴也能用；有真人录音时删掉 `synth`、填上 `audio` 与 `track` 即可走常规播放路径。
- `index.json` 里对应记 `"synth": true` 与 `audio.synth` 计数，首页与听力菜单会据此显示「语音合成」。

新增第二套原创卷时，`build/check-starter.mjs` 会自动把它纳入检查（无音频、有原文、答案齐全）。
